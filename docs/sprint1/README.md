# Документация проекта EventManagementService.API

Эта папка содержит подробную документацию для первого спринта учебного проекта **EventManagementService.API** — REST API для управления событиями на ASP.NET Core.

## Структура документации

1. **[Введение и обзор проекта](01-introduction.md)**  
   Назначение проекта, ключевые характеристики, технологический стек, структура решения.

2. **[Архитектурные решения](02-architecture.md)**  
   Слои приложения, внедрение зависимостей (DI), middleware, выбор типов интерфейсов и возвращаемых значений, потокобезопасность.

3. **[Модели, DTO и валидация](03-models-dto-validation.md)**  
   Доменная модель `Event`, Data Transfer Objects (CreateEventRequest, UpdateEventRequest, EventResponse), стратегии валидации.

4. **[Контроллер и сервисы](04-controller-services.md)**  
   Детальный разбор `EventsController` и `EventService`, их обязанности, взаимодействие, примеры кода.

5. **[Тестирование и запуск](05-testing-deployment.md)**  
   Модульное и интеграционное тестирование, запуск приложения, конфигурация, развёртывание, рекомендации для production.

6. **[Диаграммы и визуализация](06-diagrams.md)**  
   Диаграммы архитектуры, потоков данных, зависимостей компонентов (Mermaid).

## Как пользоваться документацией

- **Для изучения проекта** — начните с [Введения](01-introduction.md) и двигайтесь по разделам по порядку.
- **Для поиска конкретной информации** — используйте оглавление выше или поиск по ключевым словам в файлах.
- **Для обновления документации** — редактируйте соответствующий Markdown-файл. Диаграммы можно править прямо в коде Mermaid.

## Связь с кодом

Каждый раздел документации содержит ссылки на реальные файлы проекта (например, `Controllers/EventsController.cs`, `Services/EventService.cs`). Рекомендуется параллельно с чтением просматривать исходный код для лучшего понимания.

## Внесение изменений

Если вы вносите изменения в архитектуру или код проекта, обновите соответствующую часть документации. Поддерживайте актуальность описаний, чтобы документация оставалась полезной.
