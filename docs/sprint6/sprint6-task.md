Задание
В этом спринте вы доработаете сервис бронирования так, чтобы схема базы данных управлялась миграциями EF Core, а корректность интеграции с PostgreSQL была подтверждена интеграционными тестами на реальной базе данных.
В предыдущем спринте вы подключили EF Core. Теперь ваша задача — перейти от автоматического создания схемы к миграциям, выделить репозитории для Event и Booking и покрыть слой доступа к данным интеграционными тестами с использованием Testcontainers.
Вы создадите начальную миграцию для таблиц events и bookings, настроите применение миграций при старте приложения, инкапсулируете работу с DbContext в репозиториях и напишете интеграционные тесты, которые поднимают реальный контейнер PostgreSQL и проверяют работу слоя данных.
В результате выполнения проектной работы вы:
создадите и примените миграции EF Core для формирования схемы базы данных;
реализуете репозитории для Event и Booking с CRUD-операциями;
обеспечите корректное создание таблиц и связей через миграции;
реализуете интеграционные тесты с использованием PostgreSQL в Testcontainers;
настроите изолированное тестовое окружение для работы с реальной базой данных.
Требования и функциональность
Проект использует C#, .NET 8 и выше, ASP.NET Core Web API.
Код приложения хранится в том же публичном GitHub-репозитории.
Проект собирается и запускается стандартными средствами (dotnet build, dotnet run).
Тесты запускаются командой dotnet test и успешно проходят.
Swagger доступен и корректно отображает все эндпоинты.
Для работы с базой данных используются Entity Framework Core и PostgreSQL.
Схема базы данных управляется миграциями (Migrate()), а не EnsureCreated().
Реализован репозиторный слой для Event и Booking.
Интеграционные тесты выполняются на реальной PostgreSQL через Testcontainers.
Как работать над заданием
Этап 1. Подготовка к работе

Убедитесь, что проектная работа пятого спринта успешно завершена.
Переключитесь на ветку main вашего репозитория и выполните git pull для синхронизации.
Создайте новую ветку sprint-6 из ветки main и переключитесь на неё.
Всю работу по этому проекту ведите в ветке sprint-6.
Убедитесь, что Docker запущен — он нужен для работы Testcontainers.
Удалите локальную базу данных, которая была создана через EnsureCreated() в прошлом спринте, чтобы схема создавалась с нуля именно миграциями.
Этап 2. Подключение NuGet-пакетов

Добавьте в основной проект пакет Microsoft.EntityFrameworkCore.Design — он нужен для генерации миграций.
Создайте проект интеграционных тестов (например, EventApi.IntegrationTests) и добавьте в него пакеты: 
Testcontainers.PostgreSql;
Microsoft.EntityFrameworkCore;
Npgsql.EntityFrameworkCore.PostgreSQL;
xunit, Microsoft.NET.Test.Sdk, xunit.runner.visualstudio.
Добавьте ProjectReference из проекта интеграционных тестов на основной проект.
Убедитесь, что решение собирается без ошибок командой dotnet build.
Этап 3. Реализация репозиториев

Ранее вы выполняли операции с базой данных прямо в сервисах Event и Booking. Ваша задача — создать соответствующие репозитории на каждую из сущностей и инкапсулировать в них всю работу с DbContext. Сервисы не должны напрямую обращаться к AppDbContext.
Создайте интерфейсы и их реализации для работы с Event и Booking.
Перенесите в репозитории всю логику доступа к данным из сервисов.
Зарегистрируйте репозитории в DI-контейнере со временем жизни Scoped.
Обновите EventService и BookingService так, чтобы они обращались к данным только через репозитории.
В BookingBackgroundService используйте IServiceScopeFactory для получения репозиториев, чтобы корректно работать со Scoped-зависимостями.
Состав методов и их названия выбирайте сами, исходя из потребностей сервисов. Ревьюер проверит, что в репозиториях нет лишнего, а вся необходимая работа с данными действительно вынесена из сервисов.
Этап 4. Создание и применение миграций

Сгенерируйте начальную миграцию:
dotnet ef migrations add InitialCreate 
Проверьте, что миграция создаёт таблицы events и bookings и настраивает внешний ключ bookings.event_id → events.id.
Обновите запуск приложения в Program.cs:
удалите вызов EnsureCreated();
добавьте применение миграций через Migrate().
using (var scope = app.Services.CreateScope())
{
    var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
    db.Database.Migrate();
} 
Этап 5. Интеграционные тесты с Testcontainers

Теперь пора проверить, как у вас получилось настроить интеграцию с PostgreSQL. Для этого напишем интеграционные тесты с Testcontainers.
Вам необходимо протестировать на реальной базе данных все методы обоих репозиториев. 
Несколько подсказок, на что обратить внимание:
не забудьте проверить все вариации фильтров и пагинацию в методе получения списка событий;
позаботьтесь о чистоте и изолированности тестов: все тесты должны использовать один контейнер PostgreSQL, а база данных между тестами должна приводиться к чистому состоянию, чтобы исключить флаки (например, EnsureDeleted()
Migrate() перед каждым тестом);
тесты не должны зависеть от порядка запуска.
Запустите dotnet test и убедитесь, что контейнер поднимается автоматически и тесты стабильно проходят при повторных запусках.
Частые ошибки и способы их устранения:
Ошибка: тесты завершаются с ошибкой подключения к базе данных. Решение: проверьте, что Docker запущен и контейнер действительно стартует.
Ошибка: схема не соответствует ожиданиям. Решение: убедитесь, что используется Migrate(), а не EnsureCreated().
Ошибка: тесты влияют друг на друга. Решение: приводите базу к чистому состоянию перед каждым тестом.
Ошибка: используется захардкоженный порт подключения. Решение: берите connection string из объекта контейнера, который предоставляет Testcontainers.
Этап 6. Проверка и оформление

Проверьте приложение через Swagger: 
создайте событие через POST /events;
создайте бронь через POST /events/{id}/book;
проверьте получение данных через GET /events/{id} и GET /bookings/{id}.
Проверьте миграции: приложение запускается с Migrate(), схема создаётся без ручного SQL.
Обновите README.md: 
опишите, что схема управляется миграциями EF Core;
добавьте команды для создания и применения миграций;
добавьте информацию об интеграционных тестах и о том, что для их запуска нужен Docker.
Убедитесь, что: 
проект собирается и запускается без ошибок;
все тесты проходят успешно.
Сделайте финальный commit и push всех изменений в ветку sprint-6 на GitHub.
Этап 7. Сдача работы

Создайте pull request из ветки sprint-6 в ветку main вашего репозитория.
Скопируйте ссылку на созданный pull request.
В уроке с проектом вставьте ссылку на pull request в поле для ссылки и нажмите «Отправить».
Ревьюер проверит вашу работу. Он оставит комментарии в pull request, если потребуются правки.
После того как правки по всем комментариям будут внесены, ревьюер одобрит pull request.
Выполните слияние изменений в ветку main.
