# Реализация sprint 6

## 1. Рефакторинг сервисов

### EventService

До sprint 6 `EventService` работал напрямую с `AppDbContext`.

После рефакторинга:

- сервис зависит от `IEventRepository`;
- логика фильтрации/пагинации делегирована репозиторию;
- бизнес-исключения и валидация остались в сервисе.

### BookingService

После рефакторинга:

- сервис использует `IEventRepository` и `IBookingRepository`;
- создание брони и изменение мест события сохраняются в одном scoped-контексте;
- `SemaphoreSlim` для process-level защиты от overbooking сохранен.

## 2. Program.cs

Startup обновлен в двух ключевых точках:

1. регистрация репозиториев в DI;
2. применение миграций через `Database.Migrate()` вместо `EnsureCreated`.

## 3. Background service

`BookingProcessingBackgroundService` переведен на репозитории:

- pending ID берутся через `IBookingRepository`;
- подтверждение/отклонение выполняется через репозиторные операции;
- каждая операция обрабатывается в собственном scope.

## 4. Тестовая адаптация

Unit-тесты сервисов обновлены под новые конструкторы и DI-модель.

Интеграционные тесты разделены на наборы:

- инфраструктура контейнера;
- репозиторные тесты событий;
- репозиторные тесты бронирований;
- schema verification tests.

## 5. Итог для кодовой базы

- меньше прямой связности между бизнес-слоем и EF деталями;
- migration-first runtime вместо one-shot schema creation;
- тесты ближе к реальным условиям эксплуатации.
